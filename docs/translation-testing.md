# 翻译质量验证

运行 `npm test` 检查请求组装、明确目标语言、旧默认提示词迁移、缓存隔离、源文本保真，以及多服务和空白/标点边界组合。`npm run compile` 检查类型，`npm run build` 后执行 `npm run test:browser` 验证面板与网页划词流程。浏览器测试使用模拟接口，不能证明模型词义正确。

## 真实 DeepSeek 评估

在被 Git 忽略的 `.env.local` 中填写：

```dotenv
DEEPSEEK_API_KEY=你的密钥
DEEPSEEK_MODEL=deepseek-chat
DEEPSEEK_BASE_URL=https://api.deepseek.com
TRANSLATION_EVAL_ROUNDS=2
TRANSLATION_EVAL_CONCURRENCY=4
```

代理可填写根地址、`/v1` 地址或完整 `/chat/completions` 地址。运行 `npm run test:translation:live`，使用生产代码生成 DeepSeek 请求；禁用缓存，每个用例重复请求。此测试会产生正常的模型 API 费用。密钥不会写入测试报告。

语料见 `tests/translation-cases.mjs`，包括单字、常见单词、多义词、屈折词、大小写、重音字符、撇号和连字符、缩写、短语、习语、句子、多语言、代码与 URL，以及普通空格、不换行空格、全角空格、换行、标点、引号和括号。

每次检查译文是否包含预期词义、是否使用正确语言、是否有同一行的单词与 IPA、是否使用“英/美”标签、不同词性是否分行，以及短语是否错误附加音标。完整输出和失败原因保存在被 Git 忽略的 `temp/translation-live-results.json`。词义检查接受多种近义表达；遇到失败应检查原始输出，区分模型错误、网络错误和评估条件过窄。报告保留模型原始输出；`formatAdjustedCases` 记录默认词条格式整理的次数。自动检查不能证明所有语义细节及音标都正确，仍需抽查输出，也不能保证未来每次请求完全一致。

普通流式聊天服务使用默认 System/User Prompt 时，会检查明显错误的中文翻译方向和短语词典格式；命中时最多纠正重试一次，仍失败则显示错误并且不缓存该结果。自定义提示词及专用 MT 模型不强制应用该检查。真实评估调用相同的检查逻辑，报告同时保留首次输出和纠正输出，避免掩盖首轮问题。

## 2026-10-17 验证记录

- 模型：本机配置的 `deepseek-flash`，智能模式，temperature 0.2，无缓存。
- 修复词性分行后的完整评估：279 个不同选区，每个执行 2 次，共 558 次评估，全部通过词义、方向及格式检查，包含 service 及其空格和标点变体。
- 实际模型请求：558 次；本轮未触发纠正重试，也未触发词性格式整理，模型原始输出均通过分行检查。报告同时保留原始和最终输出。
- 代码回归：33 项通过，包含 13,680 组请求/目标语言/边界组合；这部分不是模型质量测试。另用用户报告的 service 原始输出验证格式整理、同词性分号和复合词性标签保留。
- 类型检查、扩展构建、面板与划词浏览器流程通过；浏览器流程另外验证两种入口纠正重试时都会清除错误输出并展示正确译文。
